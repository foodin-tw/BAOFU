一、什麼是 MoltBot？

快速了解 MoltBot 的定位與核心能力

📌 產品定位

MoltBot（又名 OpenClaw，前身 Clawdbot）是一款開源、可自行架設的 AI 個人助理。 不同於 ChatGPT 等純對話型工具，MoltBot 可以主動代替使用者執行實際任務，如收發郵件、操作瀏覽器、管理檔案、排程提醒等。 它需要串接大型語言模型（LLM）如 Claude、GPT、Gemini 作為「大腦」，運行在使用者自己的設備或伺服器上。

  • 開源免費，可部署在自己的電腦或 VPS 上
  • 擁有持久記憶，跨對話保留上下文
  • 可整合 WhatsApp、Telegram、Slack、Discord 等通訊平台
  • 支援插件（技能）系統，可自行擴展功能
  • 支援 macOS、Linux、Windows（WSL2）、Raspberry Pi

三、風險評估

部署與使用 MoltBot 必須正視的風險

🔴 嚴重風險（4 項）

嚴重

高度系統存取權限風險

MoltBot 預設以完整系統權限運行，可讀寫檔案、執行命令、操控瀏覽器。若系統遭入侵，攻擊者可完全控制主機。全球已有超過 40,000 個暴露實例，其中 63% 存在可被利用的漏洞。

嚴重

提示注入攻擊（Prompt Injection）

惡意指令可隱藏在郵件或網頁內容中，誘騙 AI 執行未授權操作。例如以白色背景白色文字嵌入指令，使用者無法察覺。這等同於「針對 AI 代理的釣魚攻擊」。

嚴重

憑證與機敏資料洩露

MoltBot 在本地儲存 API 金鑰、對話歷史和系統憑證。若遭入侵，攻擊者可取得 SSH 金鑰、瀏覽器 Cookie、AWS 憑證、Signal/WhatsApp 備份等所有未加密資料。

嚴重

AI 幻覺與錯誤決策風險

MoltBot 的 LLM 大腦可能自信地產出錯誤資訊（AI 幻覺），例如草擬的合約條文有誤、法規引用不實、工程計算錯誤等。建設業若依據錯誤的 AI 產出進行決策，可能造成工安事故、法律糾紛或標案失敗等嚴重後果。2024 年加拿大法院已判決企業須為 AI 聊天機器人的錯誤資訊負賠償責任。

🟠 高風險（5 項）

高

插件（技能）供應鏈攻擊

MoltBot 的第三方插件通常未經簽名審核，研究發現部分插件含有偽裝的憑證竊取程式。安裝來歷不明的插件可能直接導致資安事件。

高

遠端程式碼執行（RCE）

已有超過 12,000 個部署的實例被發現易受 RCE 攻擊，攻擊者可遠端執行任意程式，完全接管主機系統。

高

影子 AI（Shadow AI）風險

若員工未經 IT 核准自行在公司電腦部署 MoltBot，可能在無適當監督下存取內部系統與敏感營運資料，形成無法管控的安全漏洞。

高

資料跨境傳輸與個資法合規風險

MoltBot 呼叫 Claude、GPT 等海外 API 時，公司資料會傳送至境外伺服器。若涉及員工個資、業主資料或政府標案機密，可能違反我國《個人資料保護法》跨境傳輸規定。建設業常與政府機關合作，資料主權問題尤為敏感。

高

商業機密與智慧財產權外洩

若將標案報價單、工程圖說、合約草稿、成本估算等營業秘密輸入 MoltBot（進而傳送至 LLM API），可能造成商業機密外洩。競爭對手若取得這些資訊，將嚴重損害公司競爭優勢。部分 LLM 供應商可能將用戶資料用於模型訓練。

🟡 中風險（5 項）

中

API 費用失控

若未正確設定使用限制，MoltBot 的 LLM API 呼叫量可能暴增，導致單月帳單超過 200 美元（約 NT$6,300）。需設定預算上限與告警。

中

開源專案維護風險

作為開源早期專案，可能存在未被發現的漏洞，且更新速度和安全修補取決於社群。企業級支援和 SLA 保障不存在。

中

員工過度依賴與技能退化

員工長期依賴 AI 處理文書、摘要、決策輔助，可能導致專業判斷力與基礎技能下降。一旦 AI 服務中斷或產生錯誤，缺乏獨立作業能力將嚴重影響營運效率。

中

記憶中毒攻擊（Memory Poisoning）

MoltBot 的持久記憶機制可被惡意利用——攻擊者可透過精心設計的輸入，污染 AI 的長期記憶內容，導致其在後續對話中持續產出錯誤或有害的建議，且使用者可能長時間無法察覺。

中

營運中斷風險

若公司工作流程高度依賴 MoltBot，遇到 LLM API 服務中斷、MoltBot 本身故障或伺服器當機時，相關自動化流程將完全停擺。開源專案無 SLA 保障，恢復時間不可預測。

六、建議方案

若決定試用，建議遵循的安全部署步驟

🛡️ 安全部署建議

  1. 隔離環境：務必在 Docker 沙箱 或獨立虛擬機中運行，切勿安裝在存有公司敏感資料的電腦上
  2. 最小權限：僅授予 MoltBot 必要的最低權限，使用專用帳號（獨立信箱、獨立系統帳戶）
  3. 網路限制：將閘道器綁定至 localhost，不暴露於公網；使用 VPN 或 SSH 隧道存取管理介面
  4. 預算上限：在 LLM API 帳戶設定月度支出上限（如 US$50），防止費用暴衝
  5. 插件審核：僅安裝來自官方 GitHub 儲存庫的插件，避免安裝未經驗證的第三方技能
  6. 定期監控：定期檢查 MoltBot 的操作日誌，確認無異常行為
  7. 試行階段：先以個人非敏感任務試行 1~2 個月，評估穩定性後再考慮擴大使用

⚖️ 最終建議

  • MoltBot 功能強大，辦公自動化潛力顯著，但目前資安風險偏高
  • 建設公司涉及大量合約、標案、財務等機敏資料，部署 MoltBot 需格外審慎
  • 如需使用，建議先在獨立隔離環境中小規模試行，處理非機敏性質的任務
  • 目前不建議在正式營運環境或存有機敏資料的電腦上部署
  • 可持續關注專案發展，待安全性成熟後再評估正式導入
